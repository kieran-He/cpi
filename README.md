# 数学建模竞赛协作仓库

这是一个面向两人队伍的数学建模竞赛仓库。当前仓库已经保留题目附件、原始数据和已有 LaTeX 模板，并补齐了建模、编程、结果复现和论文协作所需的目录约定。

## 快速开始

在仓库根目录执行：

```powershell
.\scripts\check_repo.ps1
```

通过后，按以下顺序推进：

1. 负责人 A 阅读 `questions/` 中的题目和附件，完成根目录 `题目分析报告.md`、`术语表格.md`，并维护 `analysis/model_contract.md`。
2. 负责人 B 根据模型合同实现 `src/`，先用最小样例跑通，再生成 `results/` 和 `figures/`。
3. 两人共同核对结果后，在 `paper/` 中组织论文草稿；最终 Word/LaTeX 产物按当届官方规则生成到根目录或指定目录。

## 目录约定

```text
.
├─ questions/                 # 题目与原始附件，只读，不在此处写中间结果
├─ docs/                     # 比赛范围、规则核验、团队工作流
├─ team/                     # 双人分工、任务看板、会议记录
├─ analysis/                 # 模型合同、假设、验证计划等内部协作材料
├─ 题目分析报告.md            # Skill 固定交付物：建模阶段
├─ 术语表格.md                # Skill 固定交付物：符号、单位、术语统一
├─ src/                      # 可运行代码：数据、模型、实验、可视化
├─ scripts/                  # 检查、运行和复现入口
├─ results/                  # 运行结果表格、日志、复现清单
├─ figures/                  # raw/process/result/flow 图表
├─ paper/                    # 论文草稿、章节材料和 Checkpoint
├─ HuaweiCup23_LaTeX_Template/ # 已有模板，只读参考
└─ 使用指南.md                # 数学建模 Skill 的边界与提交前人工核对要求
```

## 两人协作原则

- A 负责题意、假设、模型合同、公式和论文主线；B 负责数据管道、算法实现、实验、图表和复现。
- `questions/`、`docs/` 中的官方/原始材料和已有模板默认只读；不要把清洗后的文件覆盖回原始附件。
- 代码、参数、输入路径和输出路径必须能从仓库根目录复现；不要依赖个人电脑上的绝对路径。
- 任何结论先落到 `results/` 的真实运行结果，再进入论文；不手填关键数值。
- 每个阶段完成后再合并，合并前先运行 `scripts/check_repo.ps1`，具体门禁见 `docs/WORKFLOW.md`。
